4  Plan

Last updated: 2026-10-01 · Task marks: ✅ DONE · 🟡 IN PROGRESS · ⛔ BLOCKED · no mark = to do Epics are ordered from very simple to advanced; each one ends in working software you can demo. Requirements (services, tools, access, data, decisions) are in docs/requirements.yml. Workflow with live status: docs/workflow.yml (rendered in the book and the ResearchReady workbook).

4.1 Scope decision (2026-10-01)

Only two things are anonymized: names of people (plus what identifies them directly: email, phone, student/employee number, bank account) and the target company (the organisation the research was for, named in input/targets.txt, one company per line, aliases after |). Other organisations, software (ERP, PLM), places, dates, job titles and published references stay readable. The target company is masked everywhere, including citations, references, URLs and the output file name. Eval set: 0 leaks of 44, 0 false positives. Users get a Dutch one-pager on local processing: docs/onepager-lokaal.html. Network isolation of the pipeline containers is requested in InstallLocalAiPackage/REQUEST-uc10-network-isolation.md; update the one-pager’s “Nog niet afgedwongen” block when that is done.

4.2 Next (2026-10-01)

  2. Remaining person false positives in the thesis: “Max depth” (table heading), “Appendix F.”.
  3. BSN (11-proof) recogniser; grow the eval set (T7).

4.3 Goal

A fully local anonymiser for research documents: a PDF or DOCX goes in, and the same document comes out with the names of people (and their email, phone, student number, bank account) and the target company replaced by stable labels (PERSOON_1, ORGANISATIE_1, …), layout intact. Everything else stays readable. The key (entity map) is kept apart. Labels are consistent across all documents. No cloud LLMs; Dutch and English.

4.4 Current status (2026-10-01, local stack)

  • Researchers can use it: files in input/, target company in input/targets.txt, python3 scripts/anonymize_folder.py; the anonymized file in the same format in output/, the key in keys/.
  • Service uc10-anonymizer on localhost:5010 (localstack); Docling works locally (async API).
  • tests/dry_run.py passes; tests/eval_detection.py: 0 leaks of 44, 0 false positives.
  • First real document: a 46-page thesis (PDF + DOCX), author, supervisors and student number removed.
  • Not built: Langfuse trace, MinIO storage (server down), network isolation (requested).
  • Book (docs/book/) and user one-pager (output/Onepager - lokaal anonimiseren.pdf) are up to date.

4.5 Definition of done

  1. A PDF or DOCX in returns the same format out, with layout preserved; the key goes to keys/. ✅
  2. Leaks and false positives are measured on an NL + EN test set and meet agreed targets. 🟡 (set of 11 texts)
  3. Dutch identifiers of people are caught: BSN, IBAN, student/employee number. 🟡 (BSN to do)
  4. Each document produces one Langfuse trace containing hashes and labels only.
  5. Outputs are stored encrypted in MinIO and versioned in Gitea.
  6. tests/dry_run.py writes passing test-results/ JSON. ✅
  7. The pipeline containers cannot reach the internet (requested in InstallLocalAiPackage).

4.7.3 T7 — Evaluation set and metrics

First real document (2026-09-30): a 46-page English master’s thesis (PDF, plus a DOCX made from it). Author, student number, supervisors and submission date are all removed from both outputs. Findings: - Heavy over-masking by the English NER: capitalised terms become ORGANISATIE/PERSOON (“Bill of Materials”, “Submission”, “Second”), journal names and cited authors in the reference list too. Safe but hurts readability. Decided 2026-09-30: published references stay readable. The reference section (heading up to the next heading/appendix) and author-year citations (“(Yin, 2018)”, “Eisenhardt (1989)”) are not detected or replaced; appendices are. Thesis: 669 → 177 masked values. Eval case cite-en guards this. - Over-masking of title-case words fixed 2026-09-30 (thesis: 177 → 59 masked values): - an NER guess whose every word also occurs in lowercase in the same document is a common word (“Submission”, “Engineering”, “Planning & Control”); emails/URLs don’t count, and a word that is part of a detected full name stays a name (“Volgens Bakker” after “Jan Bakker”); rule-based results are never dropped; - abbreviations the document defines from common words (“Enterprise Resource Planning (ERP)”), technical terms like eBOM/mBOM, and respondent codes (R1–R11) stay readable; - surnames used on their own get the full name’s label (“De Vries said” → PERSOON_3); - written-out dates in both languages are a pattern rule now (“12 May 2026” on a line without context was missed). Eval cases title-words and nl-surname-words guard this. Still masked on purpose: interviewee job titles (quasi-identifiers in a single-company case). Still over-masked: single title words that never occur in lowercase in the document (“Master”, “Submission”) and concepts like “Bill of Materials” when “bill” never does. Known trade-off: an organisation whose name is only common words (“Beter Wonen”) is left readable unless a rule catches it (“Stichting Beter Wonen”, “… BV”). - Text in images (the university logo) is not touched. - Hyphenation at PDF line breaks: Docling joins the word, the file keeps the hyphen; reported as “not found in the file” (6 values in the thesis, none personal data). - Docling needs ~6 s per page on CPU (OCR off): 4-5 minutes for the thesis. - File names hold names too (“Thesis Eva Jansen - Voorbeeldbedrijf.pdf”). Decided 2026-09-30: output is output/<name>_anon.pdf (the original name, readable, by choice); non-PDF outputs in output/<name>/; entity maps (the keys) in keys/, apart from output/ so that folder can be shared. - Labels in PDFs: embedded font (the document’s own when it has the glyphs, else Noto Sans), original size and colour; too wide → squeezed, then shrunk (floor 40 %). Short originals (citations “Yin, 2018”, terms like “ETO”) still get small labels: a 10-15 character label in the space of 2-4 characters. What: 20 annotated documents (NL + EN) with expected entities; script that reports precision/recall per type. Done when: metrics are reported per run and targets are agreed.

4.8.2 T5 — Rebuild the document 🟡 IN PROGRESS

What: replace spans in the Docling markdown and convert back with docconvert CT122 (DOCX) or render PDF. Changed 2026-09-30: the entity map is applied to the original file (/anonymize?document=true), so docconvert is not needed. DOCX: text replaced in the Word XML (body, tables, headers/footers, footnotes, comments, tracked changes, field codes, hyperlinks); author/company properties and comment authors removed. PDF: text redacted (removed) with PyMuPDF and the label written in its place; links with PII, comments, form fields, bookmarks, attachments, metadata and the structure tree removed. The service reads the file back and returns no document if any original is still in it. Done when: a DOCX in gives an anonymised DOCX out with headings and tables intact. ✅ DOCX and PDF (dry-run step 8). Still open: test on real research documents; scanned PDFs are refused (no OCR redaction); a surname hyphenated across a PDF line break is not matched (the read-back check does not catch that either); PyMuPDF is AGPL (fine for internal use, decide before distributing).
